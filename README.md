## 💡 解决什么问题

传统学习方式：
- ❌ 学完就忘，概念零散
- ❌ 不知道哪里懂、哪里不懂
- ❌ 概念之间的关系不清楚
- ❌ 学了很多但用不上

DaCapo 提供：
- ✅ **概念网络**：自动构建前置后续关系
- ✅ **掌握度追踪**：0-100% 量化掌握程度
- ✅ **自适应调整**：根据反馈调整难度和角度
- ✅ **费曼诊断**：快速检验是否真懂

## 🚀 快速开始

### 📦 安装

```bash
npx -y skills add hou-152/dacapo-learning-coordinator -g --all
```

### 🎬 第一次使用

在对话中说：

```
带我学从知识生产到 IP 定位
```

系统会：
1. 📁 创建课题目录（学习计划、概念库、资源库）
2. 📝 生成第 1 篇文章（2-5 个核心概念）
3. 🎴 同步输出概念卡（定义、解释、边界、关联）
4. 📊 开始追踪掌握度

### 📖 继续学习

读完第 1 篇后，在文章末尾的「学习反馈」区域写下：
- 测试答案
- 哪里卡住了
- 想展开什么

然后说：

```
继续下一篇
```

系统会：
- 📈 更新概念掌握度
- 🔄 根据反馈调整下一篇
- 🌐 自动构建概念网络

### 🧪 费曼诊断

想确认是否真懂某个概念：

```
费曼一下「反向创作流程」
```

系统会用 4 步法快速诊断：
1. **定焦**：明确诊断目标
2. **裸答**：用自己的话解释
3. **追问**：1 个问题深挖
4. **确认**：一句话总结核心

## ✨ 核心特性

### 1️⃣ 概念同步输出

每篇文章生成时，AI 已经知道在讲什么概念，**同步**输出概念卡，不是事后提取。

每个概念卡包含：
- **定义**：20-40 字准确定义
- **费曼一下**：50-150 字大白话解释 + 例子
- **边界**：✅ 适用场景、❌ 不适用场景、⚠️ 常见误用（默认折叠，需要时展开）
- **关联**：前置概念、后续概念
- **掌握度**：0-100%

### 2️⃣ 掌握度追踪

| 信号 | 掌握度变化 |
|------|-----------|
| 测试答对 | +30% |
| 费曼诊断通过 | +50% |
| 举出新例子 | +50% |
| 反馈具体（>50 字） | +20% |
| 说没懂 | 不变 |
| 遗忘（>30 天未复习） | 减半 |

### 3️⃣ 自适应调整

根据反馈自动调整下一篇：

| 用户信号 | 系统响应 |
|---------|---------|
| 测试答错 + 说「没懂」 | 降低抽象度，补充例子，重新讲 |
| 测试答对 + 掌握度 >80% | 进入下一个概念，提高密度 |
| 反馈 <20 字（敷衍） | 改变问法，提供选项 |
| 提出具体应用问题 | 增加案例和判断方法 |
| 同一概念 3 次未掌握 | 换角度或暂时绕路 |

### 4️⃣ 轻量费曼诊断

**只需 4 步**（不是 6 步，避免用户疲劳）：
```
定焦 → 裸答 → 追问 1 个 → 确认
```

根据表现判定：
- 裸答清晰 + 追问答对 → **真掌握** ✅ +50%
- 裸答模糊 + 追问后清晰 → **部分掌握** ⚠️ +30%
- 裸答失败 + 追问后仍模糊 → **未掌握** ❌ 不变

### 5️⃣ 疑问继承

未解决的疑问不会被遗忘：
- 📂 保存在 `assets/疑问/` 目录
- 🔍 每次生成新文章前自动检查
- 🤫 **静默处理**：不额外询问，自然融入新文章
- ✅ 本篇解决时，文章开头自然提一句「上一篇你提到 X，本篇会解决」

### 6️⃣ 伪概念检测

输出概念卡前自动检测：

**检测方法**：去掉这个词，用大白话说，还能说清楚吗？

- ❌ 「战略思维」：去掉后无法解释 → 伪概念
- ✅ 「反向创作流程」：去掉后仍能说「先找问题，再找概念，最后做内容」→ 真概念

伪概念不输出为独立概念卡，改为术语注释。

## 🛠️ 工作原理

### 阶段 1：确认课题
- 用户给出课题名称
- 创建目录结构
- 生成学习计划

### 阶段 2：读取进度
- 读取上一篇反馈
- 读取概念掌握度
- 检查未解决疑问

### 阶段 3：更新掌握度
- 根据测试答案更新
- 根据反馈内容更新
- 交叉验证（测试 vs 反馈）

### 阶段 4：决定策略
- 根据掌握度选择推进方式
- 调整难度（±1 级，保持 3 篇稳定）
- 决定下一篇主题

### 阶段 5：生成文章 + 概念卡
- 固定 9 段结构
- 同步输出概念卡
- 生成测试题（应用题 + 迁移题）

### 阶段 6：概念提取
- 自动识别承重概念（标题提到、明确定义、多次出现）
- 伪概念检测
- 输出 2-5 个核心概念

### 阶段 7：生成概念网络
- 每 3-5 篇生成一次
- Mermaid 图可视化
- 标注核心概念层

### 阶段 8：更新学习计划
- 当前进度
- 概念掌握度统计
- 下一篇方向

## 📚 使用示例

### 示例 1：新课题

**用户**：
```
带我学从知识生产到 IP 定位
```

**系统**：
```
已经生成：
- 学习计划：~/Documents/交互式学习/从知识生产到IP定位/00-学习计划.md
- 本篇文章：01.md
- 概念索引：concepts/concepts-index.json

本篇提取了 1 个核心概念：
1. 反向创作流程（掌握度 0%）

下一步：读完后，在文章末尾的「学习反馈」里写下测试答案和你的问题。
下次说「继续下一篇」，我会先读反馈再写。
```

### 示例 2：继续学习

**用户在 01.md 末尾写**：
```
1. 测试答案：B，理由是从问题出发
2. 哪里卡住了？我没看懂反向创作流程和传统流程的本质区别
3. 想展开什么？无
```

**用户说**：
```
继续下一篇
```

**系统**：
- 提取信号：测试答对 → 掌握度 +30%，但说「没看懂」→ 卡点
- 更新 `concepts-index.json`：反向创作流程掌握度 30%
- 决定策略：下一篇降低抽象度，重新讲，换角度
- 生成 `02.md`

### 示例 3：费曼诊断

**用户**：
```
费曼一下「反向创作流程」
```

**系统**：
```
第 1 步：定焦
我们来费曼诊断一下「反向创作流程」，确认你是不是真懂了。

第 2 步：裸答
先别看任何材料，用你自己的话解释一下：反向创作流程是什么？
```

**用户**：
```
就是先找到用户的问题，再去找能解决这个问题的概念，最后把概念做成内容
```

**系统**：
```
第 3 步：追问
能举个具体例子吗？
```

**用户**：
```
比如很多人不知道怎么高效开会，我就找到「会议设计」这个概念，做成一个教程
```

**系统**：
```
第 4 步：确认
好，那你用一句话总结一下：反向创作流程的核心是什么？
```

**用户**：
```
从真实需求出发，不从流量出发
```

**系统**：
```
✅ 真掌握！掌握度 +50% → 80%

已记录在 assets/费曼诊断记录.md
```

### 示例 4：生成概念网络

**用户学完 01-03.md 后说**：
```
生成概念网络
```

**系统**：
```
已生成阶段 1 概念网络：assets/概念网络-阶段1.md

本阶段共 6 个核心概念，核心概念层：
1. 反向创作流程（起点概念）
2. 自迭代环
3. 抽象上升法（方法论核心）

学习路径建议：
- 第一步：理解反向创作流程 → 看懂自迭代环
- 第二步：掌握抽象上升法 → 理解以偏概全→合集
```

## 🎯 适用场景

### ✅ 适用
- **系统性学习**：课程、书籍、系列文章
- **概念密集型内容**：方法论、理论、框架
- **需要长期记忆**：考试、技能提升、知识体系构建
- **想建立知识网络**：概念之间的前置后续关系

### ❌ 不适用
- **单篇文章阅读**：用 dbs-learning
- **纯事实性内容**：新闻、资讯
- **娱乐性阅读**：小说、散文

## 📂 目录结构

使用后会生成：

```
{课题名}/
├── 00-学习计划.md          # 进度、掌握度统计、反馈摘要
├── 01.md                    # 第 1 篇文章
├── 02.md                    # 第 2 篇文章
├── 03.md                    # 第 3 篇文章
├── assets/
│   ├── 概念网络-阶段1.md    # 阶段性概念网络（Mermaid 图）
│   ├── 费曼诊断记录.md      # 费曼诊断历史
│   └── 疑问/                # 未解决疑问
│       ├── 疑问-X.md
│       └── 处置记录.md
└── concepts/
    └── concepts-index.json  # 概念索引（名称、定义、掌握度、关联）
```
